# YouTube 自動上傳流程與條件（規劃，尚未開發）

更新日期：2026-11-17

## 1. 目標與邊界

在「音樂生成 → 封面 → MP4」完成後，自動把影片上傳到指定 YouTube 頻道，並設定標題、說明、標籤、縮圖、播放清單與隱私狀態。

本階段只做流程與條件規劃，不建立 Google Cloud 專案、不寫 API 程式、不上傳任何影片。

## 2. 前置條件

- Google Cloud 專案已啟用 **YouTube Data API v3**。
- 建立 **OAuth 2.0 用戶端（Desktop app）**，使用 `https://www.googleapis.com/auth/youtube.upload` 權限。
- 首次授權需人工在瀏覽器完成；refresh token 以 Windows DPAPI 加密保存在本機，不進 Git。
- 目標頻道已完成 Google 帳號驗證；未驗證帳號有 15 分鐘影片長度限制。
- 頻道沒有版權警告、社群規範警告或上傳限制。
- OAuth 憑證、頻道 ID、播放清單 ID 由使用者設定，不寫死在程式。

## 3. 建議流程

1. 音樂生成成功（exit 0）且輸出檔存在。
2. 封面完成（SD 封面或使用者選定封面）。
3. 自動轉出 MP4，且通過影片驗證。
4. 產生 metadata：
   - 標題
   - 說明
   - 標籤
   - 分類（Music）
   - 語言
   - 是否為兒童內容
   - 預設隱私狀態
5. 產生 1280×720 縮圖（JPG/PNG，小於 2 MB）。
6. 上傳前檢查（見第 4 節）。
7. 以 resumable upload 上傳影片。
8. 上傳成功後設定縮圖、播放清單、字幕（可選）。
9. 記錄 video ID、狀態、時間、錯誤；必要時重試。
10. 依照設定：私人待審、不公開測試、或排程公開。

## 4. 上傳前必要條件（Gate）

全部通過才可上傳：

- 生成與轉檔流程 exit code 為 0。
- MP4 存在、大小大於 1 MB、可被 ffprobe 解析。
- 影片為 H.264 + AAC、yuv420p、1920×1080 或 1080×1920、fps ≥ 1（目前預設 5 fps 靜態畫面）。
- 音軌存在且長度與音檔誤差小於 2 秒。
- 標題 1–100 字元；說明不超過 5,000 字元；標籤合計不超過 500 字元。
- 縮圖存在、1280×720、檔案小於 2 MB。
- 沒有相同內容雜湊的重複上傳紀錄（可用 `video_id` 或 SHA-256 比對）。
- OAuth token 可用；必要時可自動 refresh。
- 當日 API quota 足夠。
- 使用者已勾選「自動上傳」並選定頻道與隱私狀態。
- 若設定為公開，需人工確認或符合排程規則。

## 5. Metadata 規則

- 標題格式建議：`歌名 | 風格 / 用途`，避免誇大與關鍵字堆疊。
- 說明：
  - 第一段說明音樂風格與情境。
  - 第二段列曲目或時間軸。
  - 第三段放版權與授權聲明。
  - 若有 AI 生成內容，依 YouTube 規範揭露。
- 標籤：風格、樂器、情境、用途；避免誤導與商標濫用。
- 分類：Music。
- 語言：依頻道主要語言設定。
- 兒童內容：預設「否」，不可預設為兒童導向。
- 隱私：預設「私人」或「不公開」，確認後再公開。

## 6. 縮圖

- 1280×720，JPG/PNG，小於 2 MB。
- 以封面為主視覺，加上可讀的大標題。
- 避免文字被裁切；重要元素置中。
- 每次上傳前檢查檔案格式與大小。

## 7. Quota 與頻率

- YouTube Data API 每日預設 quota：10,000 units。
- 每次影片上傳約 1,600 units。
- 實務上每天最多約 6 次上傳，还需保留其他 API 呼叫的額度。
- 建議：
  - 測試期每天 1 次（不公開）。
  - 穩定期每天 1–3 次。
  - 超過額度時排入隔日佇列，不重試到失敗為止。

## 8. 狀態與重試

建議狀態：

`pending → validated → uploading → uploaded → thumbnail_set → playlist_set → published / failed`

- 上傳採 resumable，網路中斷可續傳。
- 4xx（權限、配額、參數）不自動重試，記錄原因。
- 5xx 與網路錯誤最多重試 3 次，採指數退避。
- 每次重試都使用同一支影片與同一份 metadata，避免重複上傳。
- 已上傳但設定縮圖失敗時，只重試設定步驟，不重新上傳。

## 9. 建議程式結構（未來）

- `AI_Music/scripts/youtube_auth.py`：OAuth 授權與 token 更新。
- `AI_Music/scripts/youtube_upload.py`：驗證、上傳、設定縮圖與播放清單。
- `AI_Music/scripts/youtube_queue.py`：佇列與狀態保存（JSON 或 SQLite）。
- `AI_Music/app/src/YouTubeUploader.cs` 或呼叫 Python 的 Runner。
- App 設定新增：啟用自動上傳、頻道、預設隱私、播放清單、標題模板。
- 憑證位置：`%APPDATA%\AIMusicGenerator\youtube_token.bin`（DPAPI 加密）。

## 10. 安全與合規

- 不把 client secret、refresh token 寫進程式或 Git。
- 只要求 `youtube.upload` 權限，不要求完整帳號權限。
- 上傳前檢查音樂與封面沒有第三方版權素材。
- 遵守 YouTube 垃圾內容、重複內容、誤導 metadata 與 AI 內容揭露規範。
- 保留上傳紀錄與原始檔案，方便申訴或刪除。

## 11. 測試計畫

1. 使用測試頻道，上傳 10 秒測試影片為「私人」。
2. 驗證 video ID、標題、說明、標籤、縮圖、播放清單。
3. 測試 token 過期、quota 不足、網路中斷。
4. 測試重複檔案不重複上傳。
5. 測試 8 分鐘與長曲（若引擎支援）之上傳。
6. 確認刪除測試影片與清理紀錄。

## 12. 分階段建議

- 階段 1：手動上傳，工具只產生 metadata 與縮圖。
- 階段 2：半自動，App 按鈕上傳為私人，人工確認後公開。
- 階段 3：全自動，通過 Gate 後排程上傳與發布。

## 13. 待決定事項

- 測試頻道與正式頻道是否分開。
